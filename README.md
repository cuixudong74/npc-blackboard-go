# npc-blackboard-go

基于黑板机制的 NPC 协同决策运行时。多个 NPC 在同一次场景推进中共享同一份
黑板事实，各自按不同的行为目标读写与订阅；行为选择随环境变化及时调整；
固定随机种子与相同输入序列下，逐帧结果完全可复现。

## 架构

```
blackboard/   黑板核心：命名空间隔离、ACL、MVCC 快照、事务、订阅、过期
arbitration/  行为仲裁：优先级 / 适用条件 / 代价竞争，确定性裁决与抢占
runtime/      决策引擎：NPC 注册表、逐 tick 推进、超时回滚、持久化
```

## 黑板语义

- **命名空间与层级**：每个事实属于一个命名空间，层级以 `/` 分隔
  （如 `world/enemy`）。授权范围 `Scope` 按前缀匹配， `"a"` 覆盖
  `"a"` 及其全部子层级，`"/"` 覆盖全部。
- **授权可见范围**：`Store.SetACL(subject, ACL)` 分别声明读、写范围。
  越权读取在快照中不可见；越权写入导致整个事务被拒绝
  （`ErrUnauthorized`），不留任何部分写入。
- **自洽快照**：读取方通过 `Store.Snapshot(reader)` 获得某一时刻的
  完整独立拷贝，之后的提交不影响该快照，绝不出现字段级混合。
- **事务（全有或全无）**：写入方用 `Store.Begin(writer)` 开启事务，
  `Put/Delete` 只进缓冲；`Commit` 原子生效并通知订阅者，
  `Rollback` 全部丢弃。一个决策周期内的写入要么全部生效要么全部回退。
- **时间与有效期**：事实携带写入逻辑时钟 `Tick`、全局单调序号 `Seq`
  与有效期 `TTL`（tick 数，0 表示永不过期）。过期事实在快照读取时
  视为不存在，不参与决策。
- **迟到与乱序**：提交即获得全序 `Seq`，后到者覆盖先到者
  （last-writer-wins，按提交顺序）。引擎保证提交顺序确定
  （按 NPC ID 字典序），因此乱序到达的并发评估结果仍有唯一确定解释。
- **订阅**：`Store.Subscribe(owner, prefix, buffer)` 非阻塞投递；
  订阅者过慢时丢弃事件并累计 `Dropped()`，慢订阅者永不阻塞写入方。

## 仲裁规则

每个 NPC 的多个行为按以下规则竞争执行权（与候选传入顺序无关）：

1. 过滤掉在当前快照下**不适用**（`Applicable` 为假）的候选；
2. **优先级**高者胜；
3. 优先级相同，**代价**低者胜；
4. 仍平局，**行为 ID 字典序**小者胜（确定性平局裁决）。

**抢占规则**：

- 新胜者优先级**严格高于**当前行为 → 抢占（`Decision.Preempted` 记录）；
- 同优先级或更低 → 当前行为继续，避免抖动；
- 当前行为条件失效或被动态移除 → 直接让位，记为失效而非抢占。

每次仲裁产出 `Decision{Winner, Preempted, Ranked, Reason}`，
`Decision.Explain()` 给出单行人类可读说明，引擎将每个 NPC 每个 tick
的裁决记入 `Engine.Trace()`，用于复盘与复现校验。

## 决策周期（Engine.Step）

1. 应用 tick 边界排队的 NPC 增删；逻辑时钟 +1；
2. 为全部 NPC 拍摄**同一时钟下**的自洽快照；
3. 各 NPC **并发评估**：只读各自快照、只写各自事务缓冲，彼此无共享
   状态，故无数据竞争，结果与调度顺序无关；
4. 按 **NPC ID 字典序**依次提交事务；执行回调失败或提交被拒 →
   整体回滚；超过 `DecisionTimeout` → 事务被丢弃，当前行为保持不变，
   不留悬挂的抢占状态。

**耗时上界**：单步 ≈ `DecisionTimeout` + 提交阶段 O(总写入数)，
慢 NPC 不会拖住整体推进。

## 配置项（runtime.Config）

| 参数 | 默认 | 说明 |
|---|---|---|
| `DecisionTimeout` | 50ms | 单个 NPC 决策耗时上界，超时即回滚该 NPC 本周期写入 |
| `SubscriberBuffer` | 64 | 订阅通道缓冲容量，满时丢弃并计数 |

`NewEngine(store, cfg, seed)` 的 `seed` 固定后，相同输入序列下逐帧的
行为选择与黑板演化完全一致。

## 动态增删与重启

- `Engine.AddNPC/RemoveNPC`：在 tick 边界生效，不打断进行中的决策；
  移除 NPC 同时清理其 ACL 与订阅。
- `Engine.AddBehavior/RemoveBehavior`：下一 tick 生效；移除当前行为时
  仲裁自动让位。
- `Engine.Save(path)` / `Load(path)`：保存/恢复最近一次**已提交**状态
  （黑板事实、逻辑时钟、全局序号、ACL、各 NPC 当前行为）。行为与执行体
  不可序列化，重启后需重新注册 NPC 行为再 `Load`，即可从断点继续，
  后续决策序列与未重启完全一致（见 `TestSaveLoadRestart`）。

```sh
go test ./... -race -count=1
```
